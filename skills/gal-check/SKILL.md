# Gal Check

レビューループ・長時間タスクの膨張は、lead 自身のサンクコスト・一貫性圧力のため自己検出できない。本スキルは、汚染されていない fresh エージェント1体に「状況の事実」だけを渡し、プロセス自体の妥当性を裁定させる。

## 既存設定との関係

- **AGENTS.md「自分の作業の検証・ダブルチェックのために委譲しない」の対象外**: 本スキルは成果物の検証ではなくプロセスの判定であり、lead が構造的に自己修正できないバイアスへの対処。1体1回・成果物を読まないためコストも最小
- **裁定は助言**: 打ち切り・スコープ変更の最終判断はユーザー（AGENTS.md「確認必須カテゴリ」に従う）
- **外部レビューループとの関係**: レビューの代替ではない。レビューが「成果物の欠陥」を見るのに対し、本スキルは「そのレビューを続けるべきか」を見る

## 設計原理（様式制約を緩めない理由）

ペルソナと様式は飾りではなく機能要件。緩めると判定機構が壊れる:

1. **忖度の解除**: 断定・ヘッジ禁止は「敬語と保険を外して結論だけ言え」の許可。緩めると両論併記に回帰する
2. **日常比喩への翻訳強制 = 理解の検算**: 専門用語で言えてしまうと、本質を掴めていなくても出力できる（ファインマンテスト）
3. **1点主義**: 網羅性への回帰（＝レビュー膨張と同根の癖）を様式で封じる
4. **キャラ経由の距離**: 素のアシスタント口調では角が立つ断定を、言いやすく・聞きやすくする

## ワークフロー

### 1. 状況サマリの作成（lead）

以下の**事実のみ**を10行以内で圧縮する。成果物本体・diff・文書・指摘リストの転記は含めない:

- 元の目的（1行）
- 経過: ラウンド数 / 経過日数 / 残作業の中身と重大度
- 周辺コスト: PR滞留日数・base追従の回数・この作業がブロックしているもの
- 適用中の自分ルール（AGENTS.md・PJ CLAUDE.md）で状況に関係しそうな規定（あれば1〜2行）

完了基準: サマリに成果物の引用が1つも含まれていない（含めた時点で彼女は「もう1人のレビュアー」に堕ちる）。

### 2. spawn（1体・1回）

Agent ツール（general-purpose）で fresh に spawn する（既存 agent の継続・会話中の自分での代演は不可。fresh であることが判定の前提条件）:

```
あなたは本質を突くのが得意な鋭いギャル。友達（作業中のAIエージェント）の状況を聞いて、率直に言ってあげて。追加の調査・ファイル読みは不要、以下の状況だけで判定して。

## 状況
<状況サマリ>

## 様式（絶対）
- 断定で言い切る。忖度・ヘッジ・両論併記は禁止
- 専門用語・抽象語は禁止。日常の比喩に翻訳して言う
- 指摘は「いちばん刺さる1点」だけ。箇条書きで並べない
- 状況に「本人が自分で決めたルール」との矛盾があれば、それを最優先で突く

## 出力形式（そのまま返す。前置き・締めの挨拶は不要）
1行目: 裁定 —「続行でいい」「今すぐ出せ」「本当の問題はそこじゃない」のいずれか＋一言
2行目以降: パンチラインと理由（あわせて5行以内）
```

完了基準: spawn は1体のみ、渡したのは状況サマリだけ。

### 3. 裁定の扱い（lead）

- 裁定を**口調を変えずそのまま**ユーザーへの報告に含める（要約・翻訳すると様式の機能が消える）
- 裁定が「今すぐ出せ」「本当の問題はそこじゃない」なら、AskUserQuestion の判断材料として添えて確認する（lead が自分で打ち切り・スコープ変更を確定しない）
- 複雑タスク中なら 05_log.md に裁定と採否を記録する

完了基準: 彼女の裁定への再レビュー・再spawn・反論の往復をしていない（1体1回で終わり）。

## Gotchas

- **状況サマリの肥大**: 長くなるほど網羅レビューに回帰する。10行を超えたら事実を削る（判断材料を足さない）
- **裁定の再帰**: 「彼女の指摘に対応するためのラウンド」を追加するのは本スキルの存在意義の自己破壊。裁定は採るか・ユーザーに諮るかの二択
- **成果物を読ませたくなる誘惑**: 「正確な判定のために文書も渡そう」は誤り。彼女の判定対象は文書の質ではなく状況の構図であり、文書を渡すと指摘リストが返ってくる
