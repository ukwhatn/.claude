# 出典と採否

各規則の出典の URL と原文の該当文は、各参照の「出典キー」節にある。本ファイルは、出典の選び方と、出典どうしが食い違う論点の採否をまとめる。

## 目次

1. 出典の選び方
2. 食い違いの採否
3. 取り込まなかったもの
4. 出典を更新するとき

## 1. 出典の選び方

- 公開されているデザインシステムと公的な指針を使う: Material（material-components-android と developer.android.com の docs）、Apple HIG、IBM Carbon、GitHub Primer、Atlassian Design System、Microsoft Fluent 2 と Windows のデザイン指針、GOV.UK Design System、Nielsen Norman Group、WAI-ARIA APG、WCAG 2.2、MDN、Vercel Web Interface Guidelines、Linear の再設計記事、Anthropic の frontend-design skill
- **複数の出典で一致する点を規則にする**。1出典だけの規則は、出典が公式で、他の出典と矛盾しないときに限る
- **原文を開いて該当文を確かめた規則だけを入れる**。確かめられなかった規則は、各参照の「未確認で外した規則」に理由と一緒に残す
- 画面幅の区切り・時間（ms）・寸法（px・dp）・不透明度などの数値は持たない。出典ごとに値が違い、PJ と CSS フレームワークの値と食い違うから。例外は、複数の出典が一致し、かつ型の選択に効く数（ボトムタブの項目数）だけ
- 原文の確認日: 2026-10-06

## 2. 食い違いの採否

| 論点 | 出典の食い違い | 採った規則 |
|---|---|---|
| ボトムタブの項目数 | Material 3〜5、HIG 5以下 | 5以下（両者が一致する範囲） |
| タブの数 | 出典により上限なし〜少数 | 数値で決めない。ラベルが1行で全部見える数までにし、溢れたら型を変える |
| 横ナビか縦ナビかの項目数 | Windows NavigationView 上部5以下・左5〜10、Carbon 二次ナビ5件超で左パネル | 数値でなく条件（少数で増えないなら横、多い・増える・頻繁に切り替えるなら縦）で書く |
| サイドナビの階層 | HIG 2段、Carbon 2段、Fluent 2段、Primer 最大4段 | 2段まで。3段目はページの中のタブか一覧と詳細の2ペイン |
| ナビゲーションドロワー | Material は非推奨にし、展開したレールで置き換える | 広い幅のサイドバーと中くらいの幅のレールを同じ項目・同じ順序にする |
| 見た目がタブのページ遷移 | Atlassian は禁止、Primer は URL が変わるタブ列を部品として持つ | URL が変わるならリンクの列（`nav` とリンクと `aria-current`）として作り、`tablist` にしない。画面の中の切り替えと1列に混ぜない |
| タブの矢印キー | 食い違いではない。GOV.UK が外したのは上下キーで、APG も横向きのタブでは上下キーを拾わない | APG に従う |
| モーダルの入れ子 | Primer は2段まで許容、Atlassian は例外なく禁止、HIG は alert だけ他のモーダルの上に出してよい | 原則禁止。例外は、閉じると作業が失われるときの確認ダイアログ1枚だけ（HIG） |
| 側面パネルのモーダル性 | Primer は常にモーダル、Material の標準 side sheet・HIG・Atlassian は背景と同時に操作する型を持つ | 元の画面を見ながら使う詳細・フィルタは非モーダルの側面パネル。作成・編集の長いフォームはページ |
| Atlassian の drawer | 非推奨化を予告している | モーダルの側面パネルは中央のモーダルと同じ条件に限る |
| 確認ダイアログの既定ボタン | NN/g は既定の答えを持たない方がよい、HIG は意図して選んだ破壊的操作なら Return で確定できる既定ボタンを認める | 破壊的な操作を既定のボタンにしない |
| toast の採否 | Primer はアクセシビリティの理由で推奨しない、Carbon・Atlassian・Material は部品として持つ | 消えても困らない結果だけに使う。エラー・読む必要がある内容・操作が必須の内容には使わない。操作付きは自動で消さない |
| 通知に付ける操作の数 | Carbon 1つ、Primer 1つを推奨、Atlassian flag 2つまで | 1つに絞る |
| 解決できない告知のバナーを閉じられるか | Primer は閉じられる、Atlassian は閉じられない | 規則にしない。両者が一致する「利用者が解決できる問題は解決まで残す」だけを採る |
| 読み込みの確定型への境目 | NN/g は10秒以上で進捗率、Primer は約3秒以上で確定型 | 1秒未満は出さない。進捗を測れない、または3秒未満なら不確定型。3秒以上かかり進捗を測れるなら確定型。測れず10秒を超えうるならバックグラウンド化か確定型 |
| 面の高さの表し方 | Atlassian は上位の面で明るさと影を併用、Material は面の色の段階 | 面の区別は明暗の段階で付け、影は浮く要素に限る。浮く要素は明暗と影を対で使う |

## 3. 取り込まなかったもの

- Material 3 Expressive を shadcn に移植したサイトの実装と数値（バネの時間・角丸の px・状態の重ね色の %）。作者とライセンスを確認できなかったため、Material の公式 docs で裏付けた考え方（動きを位置・大きさと色・透明度に分ける、状態を重ね色で表す）だけを採った
- Vercel Web Interface Guidelines のうち、英語の文字組みの規則（Title Case・曲がった引用符・省略記号）。日本語の文言は `/writing-ui-text` に従う
- Refactoring UI と、生成系サービスの system prompt。本文の一次ソースを開けなかった
- 密度の既定（業務画面は高密度にする等）。どの出典も既定を定めていない

## 4. 出典を更新するとき

- 規則を足す・変えるときは、出典の原文を開いて該当文を各参照の「出典キー」に書き、本ファイルの確認日を書き換える
- Apple HIG はページが JS で描画されるので、`https://developer.apple.com/tutorials/data/design/human-interface-guidelines/<slug>.json` を取得して読む。m3.material.io も本文を取得できないので、material-components-android の docs か developer.android.com を使う
- 要約ツールを経由した記述は、原文に無い数値・禁止が混ざることがある。要約だけを根拠に規則を足さない
