# making-slides

場面に合わない密度、主張の無いページ、確認していない PDF の崩れを防ぐため、スライドを「場面と型 → 主張の設計 → 経路 → 見た目の方向 → 本文 → ビルドと検証」の順で作る。内容を決める順序を逆にしない（本文やデザインを先に作ると、作ったものに合う主張と根拠を後から探すことになる）。

同梱ファイルはこのスキルのディレクトリ（発動したときの Base directory）にある。以下の `references/`・`templates/`・`scripts/` はそこからの相対パス。PJ にデッキのテンプレートや報告書専用のスキルがあれば、そちらの型と手順を優先し、本スキルは規定の無い論点に使う。

## 手順

### 1. 場面と型を決める

`references/deck-types.md` を読み、型を1つ選ぶ。話し手が同席するか、最終成果物が投影か PDF か両方か、で決まる。伝えるだけで相互作用が不要なら、スライドにせず文書にすることもここで判断する。

完了基準: 型、読み手、話し手の有無、成果物の形式、持ち時間かページ数、読み手が資料を閉じたときに答えられるべき問い（既定は3つまで）を書けている。投影と配布の両方が必要なときは、2版を作ると決めてある。

### 2. 主張を設計する

`references/message-design.md` を読み、資料全体の主張1文、章の主張、ページごとの主張（＝見出し）と根拠を設計表に書く。設計表をユーザーに示し、確認を取ってから本文に着手する。既存のデッキを再作成するときは、先に同ファイルの点検表で横断する問題を数える。

完了基準: 設計表の全ページに主張と根拠の出所がある。主張を書けないページは統合か削除をしてある。ユーザーが設計表を確認している。

### 3. 経路を選ぶ

- Marp
  - 選ぶとき: PDF が成果物、文章・表・コードが主体、Markdown で差分を管理したい
  - 動き: ページ送りの遷移と箇条書きの段階表示（HTML 出力だけ）
  - 検証: PDF の機械検査と PNG 目視
- HTML（reveal.js）
  - 選ぶとき: ページ内で要素単位に動かす、図が組み上がる、デモを組み込む、ライブで操作する
  - 動き: auto-animate・fragment・CSS と JS の任意の動き
  - 検証: ブラウザで全ページを送る、PDF 版は機械検査と PNG 目視

両方の条件に当たるときは、配る PDF を Marp、登壇を HTML にせず、1つの経路に決める（同じ内容を2つの形式で保守すると、修正がどちらかに漏れる）。HTML を選んでも配布の PDF が必要なら、動きの最終状態をページに残す作りにする（`references/html.md`）。

### 4. 見た目の方向を決める

- PJ・組織のテーマとブランド（色・書体・ロゴ）があれば、それに従う。元のデッキしか無いときは、色をサムネイルの画素から取り、白地の文字に使用できる色（コントラスト 4.5:1 以上）と面の塗りにだけ使う色に分ける
- 無ければ `/unslop` の Direction の5行（Product・Character・World・Moments・Signature）を、デッキの題材から書く。和文の書体を選ぶときは `/anything-frontend-art-direction` の「和文と欧文を合わせる」と書体の事例データを使う。登壇やイベントで題材に固有の見た目が必要なときは、同スキルの見本の探し方と意匠の採用条件も使う
- 文字の大きさ・コントラスト・1ページの要素数・動きの規則は `references/visual.md` に従う

完了基準: 方向（既存テーマに従うか、5行か）と、本文・見出しの書体と大きさが決まっている。新しく方向を決めたときは、5行をユーザーに確認してある。

### 5. 本文を書く

- テンプレートを作業ディレクトリに複製して書く。Marp は `templates/marp/` と `references/marp.md`、HTML は `templates/html/` と `references/html.md`
- 見出し・箇条書き・発表者ノートの日本語は `/writing-prose` を実行して書き、`/yomiyasu` で推敲する（文書の種類は `slides`。体言止めの箇条書きとページの数・順は yomiyasu 側で変えない）
- グラフ・数値のタイル・表の配色は `/dataviz` に従う
- HTML の動きをブラウザの機能（View Transitions・CSS のアニメーション・Web Animations API）で作るときは、`/modern-web-guidance` で作り方を確認する
- 数値・固有名・日付・宛名は一次情報から取り、出所を設計表に残す

### 6. ビルドして検証する

- Marp: PDF を出力し、`scripts/verify_pdf.py` で検査し、`scripts/pdf_to_png.py` で全ページを PNG にして目視する（コマンドは `references/marp.md`）
- HTML: ブラウザで最初から最後まで送り、各ページと各段階のスクリーンショットを撮って動きを確認する。動きを減らす設定（`prefers-reduced-motion`）でも送る。PDF 版を作るなら `scripts/html_to_pdf.mjs` で出力し、Marp と同じ検査と目視をする（`references/html.md`）
- 収まらないページは内容を削るかページを分ける。テーマの文字の大きさと余白を1ページのために変えない

完了基準: verify が0件でページ数が設計表と一致する。全ページの PNG（HTML は各段階のスクリーンショットも）を開いて確認した。

### 7. 提示する

成果物のパス、ページ数、目視で確認したこと、検査が見ていない範囲（文の正しさ、段の割り当て、発表の時間）を報告する。社外に渡す資料は、宛名・日付・数値の出所を並記して確認を取る。

## 既存スキルとの分担

- `.pptx` で編集して渡す資料は `anthropic-skills:pptx`、Google Slides は `anthropic-skills:google-workspace` を使う。Marp の `--pptx` は各ページを画像にするので、受け取った人は文字を編集できない
- `/designing-ui` はアプリ画面のナビゲーション・重ね方の型を扱うので、スライドには使わない
- HTML 経路の仕上げで、AI が作ったように見える兆候（色相をまたぐグラデーション、光彩、絵文字のラベル、同じ強さで並ぶ要素）を点検するときは `/unslop` の兆候の一覧を使う
- 文章の推敲は `/writing-prose` と `/yomiyasu`、英語のデッキは `/writing-prose` と `/humanizer`

## Gotchas

- 投影用のデッキを、そのまま読む資料として配らない。話し手の説明を前提にした疎なページは、単独では主張が伝わらない。逆に読む資料を投影すると、聴衆は話を聞かずに文字を読む。両方が必要なときは同じ設計表から2版を作る（`references/deck-types.md`）
- 見出しを「概要」「背景」のようなラベルにしない。ページの主張を文で書く。目次・章扉・表紙は例外
- Marp の遷移と箇条書きの段階表示、reveal.js の auto-animate は PDF に出ない。PDF で段階を見せたいときは、段階ごとにページを分ける
- reveal.js の fragment は、PDF で既定では段階ごとに別ページになる。1ページにまとめるなら `pdfSeparateFragments: false` にする
- Marp で `<` の直後が ASCII 英字の文字列（`<T>`・`<name>`）は HTML タグとして解釈され、文字が消える。閉じられないタグは以降のページを飲み込む。`&lt;` にするかコードにする
- PDF の機械検査は、文の中身・段の割り当て・図の位置を見ない。0件でも PNG を全ページ開く
- 和文の書体は、テンプレートの読み方（`@fontsource/noto-sans-jp` の固定ウェイトを node_modules から読む）を変えない。システムの和文書体（ヒラギノ）・可変フォント・疑似太字は Chrome の PDF で Type3 になって書体名が消え、検査で代替を見つけられなくなる。CDN の Web フォントはオフラインの会場とビルドで別の書体に置き換わる
- 動きは、状態の変化・順序・因果を見せるときだけ使う。装飾の動きは聴衆の注意を主張から外す。`prefers-reduced-motion` を尊重し、1秒に3回を超えて点滅させない

## 例

**例1: 社内勉強会の登壇（20分）と、後で配る資料**
型は登壇。投影版と配布版の2版を、同じ設計表から作る。動きは図の段階表示だけなので Marp を選ぶ。投影版は1ページ40語以下で見出しを主張の文にし、配布版は発表者ノートの説明を本文に移した読む資料にする。両方を PDF にして検査し、PNG を目視する。

**例2: カンファレンスの基調講演で、アーキテクチャ図が段階的に組み上がり、数値が変化する**
ページ内の要素単位の動きが主役なので HTML（reveal.js）。auto-animate で図の要素を移し、数値は fragment のイベントで動かす。題材に固有の見た目が必要なので、`/anything-frontend-art-direction` で見本を探して方向を決め、`/unslop` の5行に写す。配布用の PDF は動きの最終状態で出力する。

**例3: 既存の提案デッキが「文字が多くて読まれない」と言われた**
再作成する前に `references/message-design.md` の点検表で、主張の無い見出し・1ページに複数の役割・同じ論点の散在を数える。読み手が会議で決めることを確認し、型（会議の投影か読む資料か）を決め直してから設計表を作る。
