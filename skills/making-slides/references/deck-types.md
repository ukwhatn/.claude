# 場面別の型

目次: 1 型の選び方 / 2 登壇 / 3 会議の投影 / 4 読む資料 / 5 提案・営業 / 6 成果報告 / 7 投影と配布の2版 / 8 スライドにしない判断

## 1. 型の選び方

| 型 | 話し手 | 主な成果物 | 1ページの文字量 | 読み手が決めること |
|---|---|---|---|---|
| 登壇 | いる | 投影 | 40語以下 | 持ち帰って試すか、もっと知りたいか |
| 会議の投影 | いる | 投影（議事に残る） | 中 | その場で何を決めるか |
| 読む資料 | いない | PDF | 150〜200語 | 読んだ後に何をするか |
| 提案・営業 | いる、後で読まれる | 投影と PDF | 中 | 次の一手に進むか |
| 成果報告 | どちらも | PDF（報告会では投影） | 多い | 承認するか、次に進むか |

- 文字量は Duarte の slidedoc の目安（英語の語数。投影40語以下、読む資料150〜200語）で、実測の研究ではない。日本語の字数の目安は出典が無いので、投影は文ではなく語句と図で組み、読む資料は本文だけで意味が通る文で書く、という違いで作り分ける
- 依頼文から型が決まらないときは、「話し手が同席するか」と「最終成果物が PDF か」をユーザーに確認する

## 2. 登壇（カンファレンス・勉強会・LT・研修）

- 閉じたときに答えられる問いの例: 何が問題だったか／何をすればよいか／自分の環境で試せるか
- 構成の骨: 聴衆の問い → 主張 → 根拠（事例・データ・デモ）→ 持ち帰ってほしいこと1〜3点
- 書くこと
  - 見出しは主張の文（`references/message-design.md` §3）
  - 根拠は図・写真・コード・数値を大きく1つ。説明は話す
  - 最後のページは持ち帰ってほしいことで、質疑の間も表示しておける内容にする
- 書かないこと
  - 話す内容をすべて書いた文章（聴衆が読み始め、話を聞かなくなる）
  - 自己紹介と目次に何ページも使う構成（主張に届くまでに聴衆が離れる）
  - 読めない大きさのコード全文。要点の数行を拡大し、全文はリンクにする
- 持ち時間から枚数を決めず、リハーサルで1回通して実測する

## 3. 会議の投影（意思決定・定例・レビュー）

- 閉じたときに答えられる問いの例: 何を決めたか／決めた根拠は何か／誰が次に何をするか
- 構成の骨: 結論と決めてほしいこと（1ページ目）→ 判断材料（選択肢と比較）→ リスクと未確定のこと → 次の動き
- 書くこと
  - 1ページ目に、決めてほしいことと推奨を書く
  - 選択肢は同じ軸で比べる。推奨を1つに絞る
  - 議事に残る前提で、数値には出所と時点を書く
- 書かないこと
  - 経緯の時系列を冒頭に長く置く（判断に届くまでに時間を使い切る）
  - 推奨の無い選択肢の羅列

## 4. 読む資料（PDF 配布・事前共有）

- 閉じたときに答えられる問いの例: 要点は何か／根拠はどこまで確かか／自分は何をすればよいか
- 構成の骨: 要約1ページ（結論・根拠の要点・読み手にしてほしいこと）→ 章ごとの主張と根拠 → 付録
- 書くこと
  - 各ページの見出しを主張の文にし、本文だけで意味が通る文で書く（話し手の補足が無いため）
  - 図表には読み方を1文添える
  - 出典・定義・前提を注記に書く
- 書かないこと
  - 投影向けの短い語だけの箇条書き（話し手がいないと意味が補えない）
  - 動きを前提にした段階表示（PDF では最終状態しか見えない）

## 5. 提案・営業

- 閉じたときに答えられる問いの例: 相手の課題は何か／なぜこの解決か／次に何をするか
- 構成の骨: 相手の課題と、そのままにしたときの費用 → 解決の内容 → 証拠（事例・数値・デモ）→ 次の一手（1つ）
- 書くこと
  - 課題は相手の言葉と数字で書く（相手から聞いたこと、相手の資料）
  - 証拠は相手に近い事例を優先する
  - 次の一手は具体的な1つ（日程・担当・試す範囲）
- 書かないこと
  - 自社の紹介から始める構成（相手は自分の課題との関係を探しながら読むことになる）
  - 出所の無い効果の数値と、比較の基準の無い「業界最高」の類
  - 価格・契約条件は、ユーザーが載せると決めたときだけ書く

## 6. 成果報告（PoC・プロジェクトの完了報告・中間報告）

- 閉じたときに答えられる問いの例（完了報告）: 目標は達成したか、根拠はどこまで確かか／目標の外で何が分かったか／確定していないことは何か
- 閉じたときに答えられる問いの例（中間報告）: ここまでで何ができたか／期限内に到達するか／残りの期間で何をするか
- 構成の骨: 結論と判定 → 判定の根拠 → 目標の外で分かったこと → 確定していないこと → 次の段階
- 書くこと
  - 証拠の強さでページを分ける（`references/message-design.md` §4）
  - 判定は合意した基準の言葉で書く
  - 到達点は「〜までを実行しました」の形で書く
- 書かないこと
  - 依頼形の文（相手に記入してほしい値は送付の文面に書く）
  - 「確認中」のタグ。値が埋まらない箱はページごと外す
  - 意味づけできない数値（作業の総量・文字数・件数だけの集計）
- 案件の報告書専用のスキルがあれば、そちらの工程（一次記録の台帳・外部レビュー・送付文）に従う

## 7. 投影と配布の2版

投影と配布の両方が必要なときは、同じ設計表から2版を作る。

- 投影版: 型の規則どおりに疎に作り、話す内容を発表者ノートに書く
- 配布版: 投影版を複製し、発表者ノートの説明を本文の文に移す。図を縮めて説明の文を置く場所を作る。動きの段階はページに分けるか最終状態にする
- 2版で主張と数値を一致させる。修正は設計表から両方に当てる

1つの版で両方を兼ねると、投影には密すぎ、読むには疎すぎる資料になる。

## 8. スライドにしない判断

次のどれかに当たるなら、スライドより文書（Markdown・Docs・Confluence）を提案する。

- 話し手がいない、かつ見た目の作り込みが不要（文書のほうが書きやすく、検索と修正がしやすい）
- 読み手が細部を読み比べる（仕様・規程・手順）
- 共同で編集し続ける

伝えるだけなら文書が既定で、ライブの発表は説得や質疑のように相互作用が必要なときに使う（`references/sources.md` の fowler）。
