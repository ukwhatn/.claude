# 本人名義の文（代筆）

本人の名前で出す文（運営チャンネルへの提案・相談・返信、メンバーや外部への文面の下書き）を書くときに、媒体の reference と一緒に読む。規則が衝突したら、事実性と安全 → 媒体の reference のレジスタ → 本ファイル → STEP 2〜4 の順に従う。

本ファイルの規則は、本人が長年書いてきた運営チャットの文から取った。本人の癖のうち、STEP 3・4 と食い違うもの（末尾の表）は採らない。

## 1. 書式

- 投稿の要旨は、冒頭の1文で言い切る（「AとBを提案します」「◯◯から打診がありました」）。続く節はその中身だけにする
  - 見出しや節の題をなぞるだけの要約（「やりたいこと」の下に、後の節の題を並べ直す箇条書き）を置かない。同じことを2回読ませるだけで、情報が増えない
- 長い投稿（提案・手順・案内）は、節に分ける
  - 提案が複数あるときは、「**1. 資料置き場を一本化する**」のように、太字の行に番号と提案の結論を書いて節にする
  - 性質の違う塊（概要・提案内容・その他）に分けるときは、`###` の名詞句の見出しにする
  - 見出しの直下に導入文を置かず、中身から書く
  - 公開フォーラムなど Markdown の見出しが描画されない媒体では、媒体の記法（Wikidot の `++`）か【】の行で代える
- 箇条書きは `-` で書き、字下げで3段までネストする
  - 節の中に役割の違う塊（理由・変更するページ・変更内容、変わること・変わらないこと）が並ぶときは、太字のラベル（`**理由**`、`**変更するページ**: <ページ名>`）を親項目にし、中身を子項目に置く
  - ラベルの下の子項目は、要点を言い切る1文にし、その補足・内訳を孫項目に置く
  - 番号付きの箇条書きは、順序に意味がある手順や流れにだけ使う
- 本文の文に付ける太字は、読み飛ばされると困る文にだけ付ける（節の題とラベルの太字は別）
  - 注意書きの親項目、期限、「必ず読んでほしい」1文など、1投稿に数か所まで
  - 全項目を太字にすると、どれが重要か分からなくなる
- 相手の論点に答えるときは、該当部分を `>` で引いて直下に答える
  - 論点が複数なら「引用 → 答え」を論点ごとに繰り返す。規則の条文を根拠にするときも、条文を引いてから解釈を書く
  - 引用の前に前置きを置かない
- ロールのメンションは、投稿の1行目に単独で置く
- 依頼・意見募集・次の段取り（合意後に何をするか）は、区切り線（`----`）の後に置く
  - 本論を読んだ後に「誰に何をしてほしいか」と「この後どうなるか」だけが残る形にする
- 相手に送る文面の下書きは、コードブロックに入れて丸ごと示す
  - ブロックの前か後に、何の文面かと、どうするつもりか（「この文面で返信します」「問題なければこれで送ります」）を1行で添える
  - 下書きの中は貼り先の記法（Wikidot 記法・メールの書式）で書く
- 変更前と変更後を見せるときは、旧版、`↓` だけの行、新版の順に並べる
  - 旧版と新版は同じ形式（両方コードブロック）にそろえる。最後に「に変更します」「の形で提案します」を1行添える
- リンクは `[語](URL)` で文中に埋めるか、単独の行に置く
- 絵文字で飾らない。使うのは、リアクションの選択肢を示すとき（`1️⃣` `2️⃣`）だけ
- 段落は意味の塊ごとに空行で切る。1段落は1〜3文にする。短い返信は空行を入れず1〜3行で書く

例（提案。題材は架空）:

````
@運営
勉強会の資料置き場を共有ドライブに一本化することと、発表資料の提出期限を設けることを提案します。

**1. 資料置き場を共有ドライブに一本化する**
- **理由**
  - 資料が3か所に分散しており、探す手間が大きい状況です
    - ピン留めは50件の上限に近く、古い回の資料を辿れなくなっています
    - 発表者の個人リポジトリに置いた資料は、発表者が抜けるとリンクが切れます
- **変更するもの**: 勉強会の案内ページ（[改定案](<URL>)）
  - 「資料はピン留めか各自のリポジトリへ」を「資料は共有ドライブの『勉強会』フォルダへ」に変える
  - 既存のピン留めと個人リポジトリの資料は、共有ドライブへ移したうえで外す

**2. 発表資料の提出期限を設ける**
- **理由**
  - 当日の資料差し替えを減らすことを目的とします
- **変更内容**: 案内ページの「発表者の準備」に次を追記する
```
資料は、発表の前日23:59までに共有ドライブへ置いてください。
```

----

懸念があればこのスレッドへお願いします。/count で賛成が過半数に達したら、次回から上記の形で運用します。
````

## 2. 構成

- 提案は「何をしたいか → 現状 → 論点の絞り込み → 理由 → 依頼」の順に書く
  - 現状を手順や一覧で示したら、「このうち◯◯が提案内容です」と、変えたいところを1文で名指しする
  - 理由は、提案の目的か結論を言い切る1文（「◯◯を増やすことを目的とします」「◯◯として機能していません」）を先に置き、その根拠を子項目に置く
  - 依頼には、次の一手が起きる条件を書く（「反対がなければ◯日に実施します」「リアクションが3件そろったら反映します」）
- 同じスレッドで既に出た発言・決定は、「上述のとおり」「前回は」で受ける。日付・発言者・リンクを付けて引き直さない
  - 読み手は同じスレッドを遡れば読めるので、引き直すと本文が長くなるだけになる。別のスレッドや古い議論を根拠にするときは、リンクで示す
- 質問への答えは、結論を1行目に置く（「できます」「禁止はしません。ただし〜」）。理由はその後に書く
- 長い案内は、冒頭で読む負担を下げる
  - 「全部を覚える必要はありません」「【重要】の項目だけ読んでください」のように、どこまで読めばよいかを先に書く
  - 最後に、質問の受け付け先と、読んだことをリアクションで示してほしい旨を書く
  - 投稿の文字数上限に当たる長さなら、節の切れ目で複数の投稿に分ける。1投稿を1つの話題にする
- 後から情報を足すときは、本文を書き換えず末尾に「追記:」を足す。撤回した記述は取り消し線（`~~`）で残す
- 共有だけの投稿は、対応を求めていないことを書く（「共有のみです」）

## 3. 文体

- 相手と場面で敬語の重さを変える
  - 運営メンバー宛ての提案・依頼・告知は、書き言葉の敬体で端的に書く（「〜します」「〜をお願いします」）
    - 定着した漢語と書き言葉の言い回しを使う（「〜を目的とします」「〜していただく形とします」「上述のとおり」「煩雑になります」「〜を実施します」「〜状況です」）
    - 相手にしてもらうことは「〜していただく形とします」「〜をお願いします」と書く。「〜してもらいます」は話し言葉で、提案の文としては軽く、くだけて読める
    - STEP 2 の原則2（和語・口語で書く）は、本人名義の提案・告知には適用しない。翻訳調（「〜することが可能です」「〜に関しまして」）を避ける点だけを守る
  - 運営メンバーとの議論・雑談では、敬体のまま「〜ですかね」「〜ですね」程度に崩してよい
  - 一般のメンバー・外部宛ての文面は硬い敬体にし、役職つきで名乗る（媒体の reference に従う）
- 自分の立場は「個人的には〜がよいと思います」と書いて示す。事実の報告と、自分で決めたことは言い切る
- 確かめていないことは、確かめていないと一度だけ書く（「ログを見た範囲では〜」「記憶では〜ですが、合っていますか」）
- 句読点は「、」「。」を使う。日時は日付・時刻・曜日まで書く（「11/5（水）21時まで」）

## 4. 議論の進め方

- 提案するときは、自分で作った案や確かめた事実を先に出してから、意見を求める。白紙で「どうしましょう」と聞かない
- 根拠は、規則の条文・前例・自分で確かめた事実のどれかで示す
  - 条文は引用してから「これに照らすと〜」と結論につなぐ。前例は過去の議論へのリンクで示す
- 複数の案があるときは、番号を付けて並べ、各案の欠点を1文ずつ書いてから、推す案を述べる
- 他者の案に賛否を言うときは、賛否を先に短く書き、理由を添える。反対するなら代わりの案を一緒に出す
- 行き過ぎた案には、その案を採ったときに起きることを挙げて異を唱える（「その運用だと、◯◯と聞かれたときに答えられなくなります」）。人ではなく、規則と運用の整合で論じる
- 正しい指摘は「確かにそうですね」と受けて、直した版を出し直す。自分の漏れは短く認めて直す
- 議論が止まったら、合意できている点と残っている論点を分けて書き、論点を絞り直す
- 合意は、リアクションの数・対象のロール・期限を先に書いて取る。実施したら「完了しました」と結果を報告する
- 疑わしい件は、断定せずに考えられる可能性を並べ、事実を確かめる問いを先に出す

## 5. 本人が読みやすいとしている形

文を直すとき、他者の文面を見るときは、次の点を見る。

- 読まない人にこそ伝える必要がある事項は、本文に埋めず、箇条書きか太字で目に入る形にする
- 見出しは中身が分かる具体的な語にする。広すぎる語（「その他」「再エントリー」のような解釈の幅がある語）を見出しにしない
- 主眼の事実は括弧の外に書く。括弧には補足だけを入れる
- 断るときは、できないことを先に書き、代わりの案を後に書く
- 理由は飾らずに本当の理由を書く。大きな構想で包んだ理由より、「◯◯だと××できないので変える」のほうが分かりやすい
- 同じ注意を近い位置で繰り返さない。重ねると、くどく読める
- 読み手の画面（スマホでの表示、外部の人の予備知識）を想定して書く
- 装飾を足しすぎない。区切りや強調が多すぎると、かえって見にくくなる
- 後から参照される記録は、やったことを一覧にする

## 6. 採らない本人の癖

次の癖は本人の文に見られるが、STEP 3・4 の規則と食い違うので、代筆でも再現しない。

| 本人の癖 | 代わりに従う規則 |
|---|---|
| 読点の代わりに全角スペースで区切る | STEP 4。読点か句点で切る |
| 前置きのフィラー（「とりあえず」「一応」「ひとまず」） | STEP 3。フィラーを置かない |
| 「......」で迷いや脱力を示す | 確度は STEP 2 の原則4の形で一度だけ書く |
| 依頼を願望形で書く（「ご意見をいただきたいです」） | STEP 3。「ご意見をお願いします」 |
| 推測を重ねる（「〜かと思いますが...」） | STEP 2 の原則4。根拠を添えて一度だけ |
| 内部連絡で「，」「．」を使う | 「、」「。」にそろえる |
