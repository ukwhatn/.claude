# Claude Code 固有指示

AGENTS.md から @import され、Claude Code では毎セッション常駐する。Codex はこのファイルを読まない（対応表は `context/tool-codex.md`）。

## 委譲判断

**本節が扱うのは委譲の要否と構成だけ**。委譲すると決めた後の経路（pane か Agent tool か）・モデル・指示書の書き方・結果の回収・後片付けは `context/herdr-delegation.md` が真実源で、委譲すると決めた時点で Read する。

- **独立して並列に進められる作業単位（担当ファイルが重ならない実装・横断調査・ログ解析）が 2 つ以上あるときに委譲する**。単位が 1 つなら自分で進める。ユーザーが委譲・オーケストレーション専念を指示した場合はそれが優先する
- **自分の作業の検証・ダブルチェックには委譲しない**（外部レビューは別ベンダーで行う。`context/agent-cli-guide.md`）
- 体数は独立した作業単位の数に合わせ、**同一ファイルを複数体に編集させない**（担当が重なるなら分割し直す）。相互通信は作業中の情報交換が要るときだけ繋ぐ（Agent tool 経路は `name` を付けて `SendMessage`、pane 経路は herdr-delegation.md「委譲先とのやり取り」）
- 委譲先の報告は一次情報と突き合わせて検証してから採用する

## 委譲後の実務（1 体でも同じ）

- **委譲を起動したら、委譲先と同じ対象に自分で手を付けずにターンを終える**（どちらの結果も採用できなくなる）。完了は harness の通知で次のターンとして届く。この扱いは完了通知が届く経路（Agent tool・pane）に限り、Bash から起動したプロセスは AGENTS.md「バックグラウンドプロセスの後始末」に従う
- **Agent tool 経路**: idle 通知は催促しない。idle 通知が届いたのに最終報告が未着のときだけ、報告フォーマットを再掲して回収する。interrupted（failure）通知は初回 1 回だけ状況確認を送り、復帰後は報告を待つ（ユーザーが stop した可能性があるため復帰可否を lead 判断で決めない）
- 並列で委譲しているときのコミットは `git add <file>` で対象を選別する（`git add -A` は他の委譲先が編集中のファイルを巻き込む）
- **裁定を求められたら、判断材料が揃っている限りその場で決める**。保留してよいのは「何を待つのか」と「それが届いたら判断がどう変わるか」を書けるときだけ

## Claude Code 固有ツールの注意

- **Agent ツール**: 委譲の既定経路は pane（`bin/herdr-delegate.sh`）。Agent tool を使うのは、委譲先自身がファイルを書かない作業（`Explore` の探索・複数観点のレビュー報告・fresh な単発判定）と Herdr 外でのフォールバックに限る（`context/herdr-delegation.md`「経路の選択」「Herdr 外でのフォールバック」）
