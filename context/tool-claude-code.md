# Claude Code固有指示

AGENTS.md から @import され、Claude Code では毎セッション常駐する。Codex はこのファイルを読まない（対応表は `context/tool-codex.md`）。

## 委譲判断

本節は委譲するかどうかと構成だけを扱う。委譲すると決めた後の経路（taskboard の会話・pane・Agent tool）・モデル・指示書・結果の回収・後片付けは `context/delegation.md` が真実源で、委譲を決めた時点で Read する。

- **委譲するのは、独立して並列に進められ、それぞれが数手では終わらない作業単位（担当ファイルが重ならない実装・横断調査・ログ解析）が2つ以上あるとき**。単位が1つなら、または数回のツール呼び出しで済むなら自分で進める。ユーザーが委譲やオーケストレーション専念を指示したらそれに従う
- 自分の作業の検証・ダブルチェックには委譲しない（外部レビューは別ベンダーで行う。`context/agent-cli-guide.md`）
- 体数は作業単位の数に合わせ、同じファイルを複数体に編集させない。会話と pane を合わせて同時に6体以上起動するときは、起動前に体数と利用枠の残量（taskboard の `usage_get`）を示して確かめ、一部を codex に振る案も添える（会話と pane は lead・他のセッションと同じ5時間枠を使い、上限で待つ間ほかの作業が止まるため）
- 委譲された側（lead の指示書を受けて動いている会話か pane）はこの判断をしない。分けたほうがよいと思ったら lead に分け方を提案する（`bin/taskboard-delegate.sh`・`bin/herdr-delegate.sh` は委譲先から子を起動する tool を外している）

## 委譲後の実務

- **委譲先と同じ対象には自分で手を付けない**（どちらの結果も採用できなくなる）。独立した別の作業があれば続け、無ければターンを終える。完了は、Agent tool と pane なら harness の通知で、会話なら taskboard の知らせ（1 行目が `<!-- taskboard: delegate ... -->` の印、続く行が「[taskboard 通知] 委譲先の会話…」）で届く（Bash から起動したほかのプロセスは AGENTS.md「バックグラウンドプロセス」に従う）
- Agent tool 経路: idle 通知は催促しない。idle になったのに最終報告が届かないときだけ、報告の形式を再掲して回収する。interrupted 通知には1回だけ状況を聞き、その後は報告を待つ（ユーザーが止めた可能性があるので、再開の可否を lead が決めない）
- 並列に委譲しているときのコミットは `git add <file>` で対象を選ぶ（`git add -A` は他の委譲先が編集中のファイルを巻き込む）
- 委譲先の報告は一次情報と突き合わせてから採用する
- 裁定を求められたら、材料が揃っている限りその場で決める。保留してよいのは、何を待つのかと、それが届いたら判断がどう変わるかを書けるときだけ

## モデルとeffort

- セッションのモデルと effort は起動時に決まる。途中で変えるとプロンプトキャッシュが無効になるので、`/model`・`/effort` の変更をセッションの途中で提案しない
- Opus 5.5 で同じ問題に2回詰まったら、区切りで引き継ぎメモ（`/handoff`）を残し、Fable 5.1 の新しいセッションへ移ることを提案する
- Agent tool を呼ぶときは `model` を用途で選んで毎回渡す（省略すると親のモデルを継承する。表は `context/delegation.md`「モデルの選択」。省略は hook が拒否する）
- Agent tool を使うのは、委譲先自身がファイルを書かない作業（`Explore` の探索・Web や文書の調査・複数観点のレビュー報告・fresh な単発判定）と、会話も pane も使えないときのフォールバックだけ。ファイルを書く委譲の既定の経路は taskboard の会話（`bin/taskboard-delegate.sh`）で、使えなければ pane（`bin/herdr-delegate.sh`）
