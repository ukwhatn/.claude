# Claude Code 固有指示

AGENTS.md から @import され、Claude Code では毎セッション常駐する。Codex はこのファイルを読まない（対応表は `context/tool-codex.md`）。

## 委譲判断

**本節が扱うのは委譲の要否と構成だけ**（委譲するか・何体にするか）。委譲すると決めた後の経路（pane か Agent tool か）・モデル・指示書の書き方・結果の回収・後片付けは `context/herdr-delegation.md` が真実源で、委譲すると決めた時点で Read する。

- **Agent 定義の `"When in doubt, don't spawn."` に対し本ファイルが優先: 実装フェーズの既定は委譲とする**。自分で実装するのは、方針判断を伴う中核ファイルと、委譲の準備が実装より重い場合に限る（実装は着手前に規模を過小に見積もりやすく、「数回のツール呼び出しで終わる」の自己申告は自分でやる側に倒れる）。**実装に入る時点で、委譲構成（担当・担当ファイル・経路・model）を 1 行で宣言してから着手する**。ユーザーが委譲・オーケストレーション専念を指示した場合はそれが優先する
- 委譲するのは独立して並列化できる作業（横断調査・ログ解析・複数ファイルにまたがる実装）。**自分の作業の検証・ダブルチェックには委譲しない**（外部レビューは別ベンダーで行う。`context/agent-cli-guide.md`）
- 体数は独立した作業単位の数に合わせ、**同一ファイルを複数体に編集させない**（担当が重なるなら分割し直す）。相互通信は作業中の情報交換が要るときだけ繋ぐ（Agent tool 経路は `name` を付けて `SendMessage`、pane 経路は herdr-delegation.md「委譲先とのやり取り」）。ユーザーが「チームで」「Agent Teams で」と言ったら相互通信を使う構成を採る（`Agent` ツールでの spawn を指す。`team_name` は Deprecated）
- 委譲先の報告は一次情報と突き合わせて検証してから採用する

## 委譲後の実務（1 体でも同じ）

- **委譲を起動したら、そのターンは「<agent 名>に委譲した。結果待ち」と 1 文書いて終える**。完了は harness の通知で次のターンとして届く。**この型は完了通知が届く経路（Agent tool・pane）にだけ使う**。Bash から起動したプロセスは委譲ではなく、AGENTS.md「バックグラウンドプロセスの後始末」に従って進んでいる証拠を確認してから終える。空いた時間に委譲先と同じ対象に自分で手を付けると、どちらの結果も採用できなくなる
- **Agent tool 経路**: idle 通知は催促しない。idle 通知が届いたのに最終報告が未着のときだけ、報告フォーマットを再掲して回収する。interrupted（failure）通知は初回 1 回だけ状況確認を送り、復帰後は報告を待つ（ユーザーが stop した可能性があるため復帰可否を lead 判断で決めない）
- **Agent tool のサブエージェントの結果は Agent の返り値を使う。`.output` ファイルを Read しない**（全会話 transcript への symlink で、コンテキストを溢れさせる）。特定条件の発生を監視するときは `Monitor`、早期停止は `TaskStop`
- 並列で委譲しているときのコミットは `git add <file>` で対象を選別する（`git add -A` は他の委譲先が編集中のファイルを巻き込む）
- **裁定を求められたら、判断材料が揃っている限りその場で決める**。保留してよいのは「何を待つのか」と「それが届いたら判断がどう変わるか」を書けるときだけ

## Claude Code 固有ツールの注意

- **Agent ツール**: 委譲の既定経路は pane（`bin/herdr-delegate.sh`）。Agent tool を使うのは、委譲先自身がファイルを書かない作業（`Explore` の探索・複数観点のレビュー報告・fresh な単発判定）と Herdr 外でのフォールバックに限る（`context/herdr-delegation.md`「経路の選択」「Herdr 外でのフォールバック」）
- CLAUDE.md（AGENTS.md）・skills・hooks の設計・監査時: `context/claude-customization-guide.md` を Read
