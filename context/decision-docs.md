# 判断と報告の文書

人に判断を求めるときの出し方と、taskboard の `doc_publish` で載せる文書の型。返答の文で書いた問いは会話が進むと流れ、受信箱の依頼にもならないので、判断は文書か質問の欄に出す。

## 判断を返答の文で聞かない

- 人の判断を待つ問い（「〜でよいでしょうか」「A と B のどちらにしますか」）を、返答の文だけに書いてターンを終えない
  - 文書を読んで決める判断（計画の承認・設計の選択・2 問以上）は、下の型で文書を書き、`doc_publish` の `questions` と本文の印 `<!-- ask: q1 -->` で問う。会話は止まらない
  - 会話の流れの中で決める判断で、答えが出るまで先へ進めないものは `AskUserQuestion`（codex は `request_user_input`）
  - taskboard に結ばれていない会話は `AskUserQuestion`
- taskboard に結ばれた lead の会話では、文書も質問も出さずに問いの文でターンを終えると、taskboard の Stop hook が 1 回差し戻す
- 判断を含む報告は文書に載せ、返答には結論・文書の題・決めてほしいことだけを書く。判断を含まない報告は返答に書く

## 文書の型

4 つのどれかで書き、節の順と名前を変えない。答えてほしい問いは、末尾にまとめず、判断の材料を書いた段落の直後に印で置く。

### 判断の依頼

1. 冒頭の 1 文: 推奨と、決めてほしいこと
2. 問いごとの節: 背景・判断の材料・trade-off を書き、直後に印を置く。推奨は 1 つにし、選択肢の `recommended` で示す
3. 採らない案: 1 案を 1 行で、採らない理由を添える

### 作業の報告（判断を含むもの）

1. 結果: 冒頭の 1 文で、何が終わり何が分かったか
2. 確認した操作と結果
3. 利用者が確認すること: 画面・操作・期待する結果
4. 残り: 終わっていないことと、その理由
5. 決めてほしいこと: 問いごとに材料と印

### 計画

1. 冒頭の 1 文: 推奨する進め方
2. 作るもの
3. 作らないもの: 頼まれていない機能・先送りしたもの
4. 確認の方法: 何を動かし、何が出れば完了か
5. 問い: 問いごとに材料と印

### 修正の提示

- 項目ごとに、修正前・修正後・前後の文脈（その節が何の話か）を並べる。変えた 1 文だけを見せない
- taskboard の文書では `doc_publish` の `changes`（`before`・`after`・`context`・`title`）に入れ、本文の該当箇所に印 `<!-- change: id -->` を置く。アプリが左右に並べ、変わった部分に印を付ける
- 推奨を 1 つ反映した形を見せ、迷うときだけ 2 案まで出す

## 4 つに共通して書かないもの

- 経緯・言い訳・却下した案の詳細（後から見返す記録はメモリディレクトリに残す）
- 同じ一覧の繰り返し（冒頭と末尾で同じ項目を並べ直さない）
- 読み手の判断を変えない但し書き
